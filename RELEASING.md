# Релизы

Релизы собираются через тег на коммите в `master`. Пуш тега (или коммита с тегом) запускает воркфлоу
`Release` (`release.yml`), который прикрепляет собранные бинарники
к черновику релиза на GitHub.

## Версионирование

Имя тега: `<апстрим>-SS220.<ревизия>`, например `7.0.0-SS220.1.0`:

- `7.0.0` — версия апстрима [tgstation/rust-g](https://github.com/tgstation/rust-g), на которой основан форк.
- `SS220.1.0` — наша ревизия поверх базы. Бампается при изменениях форка.

Важно чтобы `version` в `Cargo.toml` совпадала с тегом релиза!

## Как выпустить (Visual Studio Code)

1. Запушить нужные изменения в `master` обычным образом.

2. Когда нужен релиз — поставить тег на последний коммит `master`:

   - `Ctrl+Shift+P` → `Git: Fetch` — фетч свежего `origin/master`.
   - `Ctrl+Shift+P` → `Git: Create Tag` → ввести имя (например `7.0.0-SS220.1.0`).
   - На следующем шаге выбрать ветку для тега: `origin/master`. Тег назначается коммиту напрямую, чекаутить `master` не нужно.
   - Запушить: `Git: Push Tags`.

3. Открыть черновик на
   [странице релизов](https://github.com/ss220club/rust-g/releases) и после исполнения экшена `Release` проверить:

   - Прикреплены все 7 файлов: `rust_g.dll`, `rust_g.pdb`, `rust_g64.dll`,
     `rust_g64.pdb`, `librust_g.so`, `librust_g64.so`, `rust_g.dm`.
   - Автогенерированные релиз-ноты на месте.

4. Отредактировать релизное описание. Формат: строка сводки, затем чейнджлог
   (фичи, фиксы, мерж с апстримом) и ссылка full-compare на предыдущий тег.
   Шум вроде списка контрибьюторов убрать, если пользы он не несёт.

5. Опубликовать релиз.

## Обновление на билдах

Релиз только публикует бинари - на наших билдах бинарники не обновляются автоматически.
Для обновления:

1. Скопировать `rust_g.dll` и `rust_g.dm` из релиза в корень репозитория
   билда (рядом с `.dmb`).
2. Если билд использует нестандартный набор фич, `rust_g.dm` нужно
   сгенерировать локально через `cargo build --features ...`, а не брать из релиза.
3. Закоммитить и задеплоить обычным образом для этого билда.

## Особенности

- `release.yml` забирает бинарники из **последнего успешного исполнения `rust.yml`
  на `master`**, а не из коммита тега. Тегать можно только коммит, CI которого
  уже успешно исполнился — иначе в релиз попадут бинарники предыдущего исполнения.
  Между успешным исполнением воркфлоу и пушем тега в `master` ничего нельзя мержить.
- Теги защищены от удаления - это заблокировано правилами репозитория. Запушенный
  тег остаётся, поэтому перед пушем нужно перепроверить имя и коммит.
- x64-артефакты (`rust_g64`, `librust_g64`) нужны только для утилит и тестов.
  Самому BYOND требуется 32-битная `rust_g.dll` / `librust_g.so`.
